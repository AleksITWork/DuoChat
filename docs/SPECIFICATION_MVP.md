## 1. Введение

### 1.1. Назначение документа

Данный документ описывает требования к минимально жизнеспособной версии (MVP) мобильного приложения
DuoChat — чата для двух пользователей. Документ является основой для разработки, тестирования
и защиты курсового проекта.

### 1.2. Цель проекта
Разработка мобильного приложения DuoChat для обмена текстовыми сообщениями между двумя
пользователями в реальном времени.

### 1.3. Область применения
Приложение предназначено для личного общения между двумя пользователями. Может использоваться как
учебный проект для демонстрации навыков мобильной разработки на Android.

---

## 2. Общее описание продукта

### 2.1. Место продукта

DuoChat - самостоятельное мобильное приложение для ОС Android. Оно взаимодействует с облачными
сервисами Google Firebase (Authentication, Cloud Firestore) и локальной БД SQLite (через Room).

### 2.2. Функции продукта (кратко)

- Регистрация и авторизация пользователей
- Управление профилем
- Поиск собеседника
- Создание чата между двумя участниками
- Обмен текстовыми сообщениями в реальном времени
- Локальное хранение сообщений

### 2.3. Ограничения

- В чате будут только два пользователя
- В чате будут использоваться исключительно текстовые сообщения
- Приложение будет работать только на ОС Android

## 3. Функциональные требования

### 3.1. Регистрация пользователя

**Описание:** новый пользователь может создать аккаунт.

**Входные данные:** имя, email, пароль.  
**Выходные данные:** успешная регистрация и автоматический вход.

**Сценарий:**
1. Пользователь открывает приложение.
2. Пользователь переходит на экран регистрации.
3. Пользователь вводит имя, email, пароль.
4. Пользователь пытается зарегистрироваться.
5. Система создаёт аккаунт в Firebase Authentication.
6. Система создаёт документ пользователя в Firestore.
7. Пользователь автоматически входит и попадает на главный экран.

**Критерии приёмки:**
- Email должен быть валидным.
- Пароль — не менее 8 символов, с заглавными и строчными латинскими буквами и хотя бы одной цифрой.
- При ошибке отображается понятное сообщение.

---

### 3.2. Авторизация (FR-02)

**Описание:** зарегистрированный пользователь может войти в аккаунт.

**Сценарий:**
1. Пользователь открывает приложение
2. Пользователь вводит валидные email и пароль.
3. Система проверяет данные через Firebase Authentication.
4. При успехе — переход на главный экран.
5. При ошибке — отображается сообщение.

---

### 3.3. Выход из аккаунта (FR-03)

**Описание:** пользователь может завершить сеанс.

**Сценарий:**
1. Пользователь открывает меню профиля.
2. Пользователь выходит из аккаунта.
3. Система очищает локальную сессию.
4. Пользователь возвращается на экран авторизации.

---

### 3.4. Просмотр профиля (FR-04)

**Описание:** пользователь видит свои данные.

**Отображаемые поля:** имя, текстовый идентификатор, email.

---

### 3.5. Редактирование профиля (FR-05)

**Описание:** пользователь может изменить имя и описание.

**Сценарий:**
1. Пользователь открывает меню профиля.
2. Пользователь открывает редактор профиля.
3. Пользователь изменяет нужные поля.
4. Пользователь сохраняет изменения.
5. Данные обновляются в Firestore и локально.

---

### 3.6. Поиск пользователей (FR-06)

**Описание:** пользователь может найти другого пользователя для создания чата.

**Входные данные:** строка поиска (текстовый идентификатор).  
**Выходные данные:** список найденных пользователей.

**Сценарий:**
1. Пользователь открывает экран поиска.
2. Пользователь вводит текстовый идентификатор.
3. Система выполняет запрос к Firestore.
4. На экране отображается список результатов.
5. Пользователь выбирает пользователя и создаёт чат.

---

### 3.7. Создание чата (FR-07)

**Описание:** создание приватного чата между двумя пользователями.

**Правила:**
- Между двумя пользователями может быть только один чат.
- Если чат уже существует — открывается существующий.

---

### 3.8. Отправка сообщений (FR-08)

**Описание:** пользователь отправляет текстовое сообщение в чат.

**Сценарий:**
1. Пользователь вводит текст.
2. Пользователь отправляет сообщение.
3. Сообщение сохраняется в Firestore.
4. Сообщение сохраняется локально в Room.
5. Сообщение отображается в чате.

---

### 3.9. Получение сообщений в реальном времени (FR-09)

**Описание:** приложение автоматически получает новые сообщения собеседника.

**Механизм:** Firestore Snapshot Listener.

---

### 3.10. Локальное кэширование (FR-10)

**Описание:** последние сообщения сохраняются в Room для офлайн-просмотра.

**Правила:**
- При наличии интернета данные синхронизируются с Firestore.
- При отсутствии интернета отображаются кэшированные данные.

## 4. Нефункциональные требования

### 4.1. Производительность
- Загрузка списка чатов: не более 2 секунд.
- Отправка сообщения: не более 1 секунды.
- Плавная прокрутка списка сообщений (60 FPS).

### 4.2. Безопасность
- Пароли не хранятся в открытом виде (используется Firebase Authentication).
- Правила Firestore Security Rules ограничивают доступ к данным только их владельцам.
- Передача данных — по HTTPS.

### 4.3. Надёжность
- Отсутствие крашей при штатных сценариях использования.

### 4.4. Удобство использования
- Интерфейс соответствует Material Design 3.
- Поддержка светлой и тёмной темы.
- Понятные сообщения об ошибках.

### 4.5. Совместимость
- Минимальная версия Android: 8.0 (API 26).
- Целевая версия: Android 14 (API 34).

## 5. Архитектура приложения

### 5.1. Архитектурный паттерн
MVVM (Model-View-ViewModel):

- **View** — Compose-экраны.
- **ViewModel** — хранит `UiState`, обрабатывает действия пользователя.
- **Model** — репозитории, источники данных.

### 5.2. Стек технологий

| Слой | Технология |
|---|---|
| UI | Jetpack Compose |
| Архитектура | MVVM |
| Локальная БД | Room |
| Удалённая БД | Cloud Firestore |
| Авторизация | Firebase Authentication |
| Навигация | Jetpack Navigation Compose |
| Асинхронность | Kotlin Coroutines + Flow |
| Язык | Kotlin |

## 8. Критерии приемки MVP

Проект считается реализованным, если:

- [ ] Пользователь может зарегистрироваться и войти
- [ ] Пользователь может отредактировать профиль
- [ ] Пользователь может найти другого пользователя
- [ ] Пользователь может создать чат
- [ ] Пользователь может отправить сообщение
- [ ] Собеседник получает сообщение в реальном времени
- [ ] Сообщения кэшируются локально
- [ ] Приложение не крашится при штатных сценариях
- [ ] Интерфейс соответствует Material Design 3
